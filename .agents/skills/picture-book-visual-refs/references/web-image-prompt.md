# Web画像生成プロンプト規約

brief の画像運用モードが `Webプロンプト手渡し` のときに使う。エージェントは
プロンプトと添付一覧を作り、Webサービスへの入力と画像生成はユーザーが行う。

## 提示順

1. **用途:** 作品名、頁ID、参照／ラフ／本番候補の別
2. **必須添付:** ファイル名、版、何の正本か、何を拘束する参照か（構図／人物／場所／小道具／ルック・色調）。当該頁に必要なものだけ
3. **変えてはいけない要素:** brief と character の固定項目
4. **場面:** pagination / prose に基づく人物、行動、感情、画角、光
5. **変えてよい要素:** ポーズ、表情、画角など、その頁で許容する範囲
6. **参照間の優先順位:** 複数の参照が競合した場合に、どの要素をどの参照へ合わせるか
7. **排除事項:** 意図しない文字・数字・擬音・フキダシ・矢印・記号・キャプション・UI・番号ラベル・看板・背表紙文字・実在ロゴ、不要な人物や家具、基準にない小道具部品
8. **出力:** 縦横比、必要な余白、候補数。後工程で文字を置く場合は安全域

## 参照画像の扱い

- 添付枚数を固定しない。構図とルック／色調の参照が異なる場合は分け、それぞれの役割を明示する。
- 色調を揃えるときは、「白くする」「赤みを完全に消す」などの極端な増減指示ではなく、採用済みルック参照の紙色、水彩階調、肌色、彩度、明暗、コントラストのどれを維持するかを書く。白飛びや階調消失を避ける条件も必要に応じて添える。
- 直前頁の生成結果を次頁の唯一の色調参照として連鎖させない。採用済み正本を毎回参照し、新しい画像を正本へ昇格するなら人の採用と版を記録する。
- 文字の存在感だけが必要なら、読める文字の生成を求めず、「特定の文字・数字・言語として読めない、素朴な鉛筆の筆跡や柔らかな波線」のように視覚要素として指定する。
- 小道具が別カテゴリへ誤認されやすい場合に限り、素材、構造、用途を短く添える。案件固有の材質や形を共通テンプレートへ固定しない。

## 管理情報と入力文の分離

頁ID、ファイルパス、版、採否記録などの手渡しメモと、Webサービスへ貼る生成指示を分ける。管理用の番号や装飾が画像内容として解釈される可能性を減らし、利用者が貼る範囲を明確にする。

## 出力テンプレート

手渡しメモ:

```text
用途: <作品 / 頁ID / 成果段階>
添付:
- <path@version>: <正本の種類 / 拘束する要素>
```

Webサービスへ入力する生成指示:

```text
参照の役割:
- <構図参照は人物配置と画角を拘束する>
- <ルック参照は紙色、水彩階調、肌色を拘束する>

参照間の優先順位:
- <構図は構図参照、色調はルック参照を優先する>

固定:
- <舞台、外見、左右配置、キー小道具の構造>

場面:
<誰が、どこで、何をし、どんな感情か。画角と光。>

許容する変化:
- <ポーズ、表情、画角など>

排除:
- 意図しない文字、数字、擬音、フキダシ、矢印、記号、キャプション、UI、番号ラベル、看板、背表紙文字、実在ロゴ
- <案件固有の不要物や禁止要素>

出力:
<比率、余白、安全域、候補数>
```

サービス固有の構文は案件メモに残し、この規約の正本へ固定しない。生成後は
ファイル、使用プロンプト、添付した正本の版、人の採否を頁IDへ紐づける。
