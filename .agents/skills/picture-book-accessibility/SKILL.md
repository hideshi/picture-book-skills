# 工程9c（任意・推奨）: 絵本アクセシビリティ

絵本におけるアクセシビリティ（視覚・色覚多様性・読書困難・音声読み上げ）を計画・実装・検証する。
絵本の核である「文」と「絵（情景描写）」が相互補完する特性を踏まえ、本文・画像説明・`alt`・読み上げ順序を分離して設計し、規格準拠メタデータと台帳を整備する。
状態は `_shared/process-state.md` に従う。

## 担当

- **AI:** 画像・文に基づく客観的かつニュアンスを保った情景描写のドラフト作成、コントラスト測定、EPUBメタデータ生成、機械的整合性検証（lint）
- **著者／人間:** 画像説明の表現・雰囲気・トーン確認（過剰解釈の抑制・読み聞かせリズムの維持）、アクセシビリティ目標レベルの決定、最終採否
- **当事者／専門家（必要時）:** スクリーンリーダー利用者や支援技術専門家による実機読み上げ検証の実施とフィードバック

AIは著者の承認なしに「適合」「完全アクセシブル」を宣言しない。

## 進行フェーズ

| フェーズ | 開始条件 | 主成果物 | 目的と完了条件 |

| **相B2**（epub工程内） | rights-export済、B1確定、EPUB生成後 | EPUB実ファイル内の検証記録 | B1台帳の `img_alt` とメタデータがEPUBへ反映され、リーダー・検証ツールを通過することを確認 |

※ B1の完了条件にEPUB実ファイルを含めない（循環依存の解消）。B2の実機・ファイル検証は `picture-book-epub` 工程内で実施する。

## 手順

1. **方針と対象の確認:**
   - `brief.md` から対象読者（弱視、全盲、色覚多様性、読書困難等）、配信先、目標規格（例: EPUB Accessibility 1.1 - WCAG 2.1 Level AA）と選定理由を確認する。
2. **ページ別フィールドの設計・作成:**
   - 単一の文字列ではなく、以下のフィールドを区別して作成する：
     - `body_text`: 採用本文（読み聞かせの言葉）
     - `visual_description`: 絵が補完・追加する物語情報（人物、姿勢、表情、小道具、変化）
     - `img_alt`: 実際に `<img>` の `alt` 属性に設定する文字列（実装方式に応じて合成または分離）
     - `extended_description`: `alt` に収まらない長文詳細説明（必要時）
     - `decorative`: 装飾画像判定（yes/no と理由。yesの場合は `alt=""`）
   - **実装方式別の規則:**
     - **全頁画像・焼き込み本文（固定レイアウト）:** `img_alt` に本文と重要な視覚情報の両方を含める。
     - **独立HTML文字＋画像:** `img_alt` には本文を反復せず、絵が追加する視覚情報のみを記述する（二重読み上げの防止）。
     - **文なし頁:** 物語上の視覚情報を必ず `img_alt` に含め、読み飛ばしや沈黙を防ぐ。
   - 詳細は [絵本画像説明・代替テキスト作成ガイドライン](references/alt-text-guidelines.md) を参照。
3. **視覚アクセシビリティの検証:**
   - **コントラスト比:** 文字と背景のコントラスト比が 4.5:1 以上（大きな文字は 3:1 以上）あることを確認。背景色に変化やグラデーションがある場合は最小比率を採用し、測定領域・数値を記録する。
   - **色覚多様性:** 色の違い（赤/青など）のみに依存した情報伝達をしていないか確認。
   - **タイポグラフィ:** ユニバーサルデザインフォント等の可読性、小画面での視認性、自然な文節の改行を確認。
4. **EPUB メタデータの設計:**
   - W3C EPUB Accessibility 1.1 の MUST / SHOULD 項目を設計する：
     - `schema:accessMode`（MUST）: `textual`, `visual`
     - `schema:accessibilityFeature`（MUST）: 検証済みの機能のみ（`alternativeText`, `readingOrder`, `tableOfContents`, `pageNavigation` 等）
     - `schema:accessibilityHazard`（MUST）: `none`（または該当するハザード）
     - `schema:accessModeSufficient`（SHOULD）: `textual,visual`、および詳細代替テキストで完結する場合は `textual`
     - `schema:accessibilitySummary`（SHOULD）: 対応状況と固定レイアウト上の制約を平易な日本語で記述
   - 適合宣言（`dcterms:conformsTo`）は評価主体・評価手順が確定している場合のみ付与する。
   - 詳細は [EPUBアクセシビリティメタデータ規約](references/epub-a11y-metadata.md) を参照。
5. **配信先ストアの要件照合:**
   - 配信チャネル（Amazon KDP、Google Play Books、Apple Books等）ごとのアクセシビリティ仕様・管理画面申告項目（alt、非リフロー申告、文字拡大方式等）を確認し、台帳に記録する。
6. **台帳（`accessibility.md`）の記録と確定（相B1完了）:**
   - 下記の標準スキーマに従って `accessibility.md` を作成・更新し、著者が内容を確認して `確定` とする。

## 完了条件

### 相B1（台帳確定）
- `accessibility.md` が標準スキーマで作成され、全ページ（表紙・本文・奥付）のフィールドが埋まっている
- 文なしページに意味のある情景描写が存在し、空白になっていない
- 文字と背景のコントラスト比、色覚配慮の測定・確認記録がある
- EPUBメタデータ（MUSTプロパティ）が正しく定義されている
- 人間（著者）が内容と読み上げリズムを確認し、状態が `確定` している

### 相B2（EPUB工程での検証）
- EPUBビルダーにより、B1の `img_alt` とメタデータが実ファイルに反映されている
- `check_accessibility.py` の機械検証をエラーなしで通過している
- 少なくとも1つの読書システム／スクリーンリーダー環境で読み上げ順序・代替テキストの動作が確認されている

## やらないこと

- 画像だけのページに「1ページ」「挿絵」などの形式的ラベルだけを付けて完了とする
- 独立HTML本文がある場合に、`img_alt` に本文を重複させて二重読み上げを起こす
- 装飾画像にまで意味のあるテキストを強制し、空alt（`alt=""`）の適用を妨げる
- 著者の意図を超えた過剰な心理描写やネタバレを画像説明に盛り込む
- 評価証拠がない状態で「アクセシビリティ完全適合（conformsTo）」を自称する
- EPUB実ファイルの有無をB1台帳確定の必須条件にして工程循環を引き起こす
