# 工程11（任意）: Kindle 向け EPUB

確定本文と本番絵から、Kindle 配信可能な EPUB を作る。**実装ツール名は特定ベンダーに固定しない。**
状態は `_shared/process-state.md` に従う。

## 担当

- **AI／ツール:** 変換パイプライン案、ファイル配置チェック、EPUB 構造の抜け指摘、変換実行の手順下書き
- **人:** メタデータ・目次・権利表示の最終確認、プレビューでの読み味、公開／アップロード判断

## 前提

- `prose.md`・本番絵・`rights.md`（少なくとも節A）が **確定** または出荷可能な状態
- brief で成果物に Kindle／EPUB が選ばれている（または本工程を明示開始）
- readthrough 相 B 済みが望ましい（brief の短いパスで省略する場合はその旨を残す）

## 手順

1. brief の媒体メモを確認する（再フロー EPUB か、絵本向け固定レイアウトか。未指定なら **再フロー（reflow）を既定** とし、固定が必要なら人が明示）。
2. 入力を揃える: 確定本文（頁対応）、本番画像（解像度・色空間・命名）、表紙、権利・AI 開示文。
3. パッケージ要件をチェックリスト化する（ツール非依存）:
   - 必須メタデータ（タイトル、著者、言語、識別子）
   - 目次（目次項目と本文アンカーの対応）
   - 画像と本文の対応（欠け・順序違いなし）
   - 権利・免責・AI 開示の掲載位置
   - 再フロー時の読み順・画像代替テキスト（必要な範囲）
4. 変換を実行する（使用ツールは案件で選ぶ。スキル本文に固有名を焼き込まない）。
5. 実ファイルを開き検証する: 頁／画像の欠け、目次ジャンプ、はみ出しや極端な改行崩れ、メタデータの誤り。
6. 人がメタデータ・目次・権利表示を最終確認し、状態を `確定` にする。

## 完了条件

- EPUB 実ファイルがあり、置き場が分かる
- メタデータ・目次・権利表示を **人が** 確認した記録がある
- 画像／本文の欠け・順序違いが未解決のまま残っていない
- brief の Kindle パスと矛盾しない

## やらないこと

- 未確定の本文・絵で「納品 EPUB」と宣言する
- 権利・開示を省略したまま配信する
- 特定変換ソフト名をスキル正本に固定する
- 人の確認なしにメタデータ／目次を「確定」と書く
