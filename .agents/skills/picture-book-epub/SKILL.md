# 工程11（任意）: Kindle 向け EPUB

確定本文と本番絵から、Kindle 配信可能な EPUB を作る。**実装ツール名は特定ベンダーに固定しない。**
状態は `_shared/process-state.md` に従う。

## 担当

- **AI／ツール:** 変換・書き出しの実行、機械的な構造チェック（必須項目・リンク・頁欠けなど）、チェックリスト下書きと抜け指摘
- **人:** メタデータの採用、読み味（プレビュー）、最終成果物の採用、公開ステータス（承認／保留／未実施／実施済み）の判断
- 変換ツールが無い・動かない場合は **具体的なブロッカー** を列挙する。実ファイルなしで完了にしない

## 前提

- **納品・配信用の開始:** `prose.md`・本番絵が **確定**、`rights.md` 節A が完了条件を満たし、節B の書き出し検証（分岐前の確認用）が済んでいる
  - プロトタイプ／試し変換のみなら、上記の一部が `下書き` でも開始してよい。ただし成果は納品 EPUB と混同せず、目的を記録する
- brief で成果物に Kindle／EPUB が選ばれていること。**本工程を明示開始した場合は、チャネル選択を brief に書き戻す**
- readthrough 相 B 済みが望ましい。短いパスで省略する場合は `process-state.md` の例外記録（対象成果物・スキップ・人の判断）を残す
- rights-export 節B の検証対象は **分岐前の書き出し** であり、本工程の最終 EPUB そのものではない（最終 EPUB は本工程で別途確定する）

## 手順

1. brief の媒体メモを確認する（再フロー EPUB か、絵本向け固定レイアウトか）。
   - 未指定なら **再フロー（reflow）を既定** とする
   - 固定レイアウトは brief／人の **明示** があるときだけの代替条件。再フローが要求されているときに固定で代用しない
2. 入力を揃える: **採用本文を画像から独立したテキスト**として用意（頁対応）、本番画像、表紙、権利・AI 開示文。
3. パッケージ要件をチェックリスト化する（ツール非依存）:
   - 必須メタデータ（タイトル、著者、言語、識別子）
   - 目次（目次項目と本文アンカーの対応）
   - 画像と本文の対応（欠け・順序違いなし）
   - **頁 ID と読み順**の対応チェック
   - 権利・免責・AI 開示の掲載位置（成果物内または公開付帯文に実際に反映）
   - 再フロー時: 読み順、画像代替テキスト（必要な範囲）、**文字サイズ／表示幅の変更による崩れ確認**
4. 変換を実行する（使用ツールは案件で選ぶ。スキル本文に固有名を焼き込まない）。
5. 検証を分けて記録する:
   - **構造検証**（パッケージ・必須項目・リンク・頁対応）
   - **読書環境での確認**（実機／ビューアでの表示。構造検証の合格だけでは足りない）
   - 再フロー指定時はリサイズ確認の結果を残す。不合格は解消してから先へ進む
6. 本工程で追加・変更した素材（フォント、表紙加工、埋め込み画像など）があれば `rights.md` を更新する。当該チャネル向けに未確認項目を残さない。不使用の素材は「不使用」で閉じてよい
7. 案件記録（スキル正本ではない）に、使ったツール／版、入力の版、出力パス、実行手順、検証結果を残す
8. 人がメタデータ・読み味・最終成果を採用し、成果物状態を `確定` にする。公開ステータスは別記（アップロードがスコープに入るかも明示）

### 戻り先

- レイアウト／パッケージ不備 → 本工程内で直し、必要なら再変換
- 本文・絵の中身 → 上流 craft へ戻し `要再確認`
- 新規素材の権利 → rights-export 節A
- チャネル変更 → brief

## 完了条件

- EPUB 実ファイルがあり、置き場が分かる（ツール欠如のまま完了にしない）
- **選択形式への適合**（再フロー指定なら再フロー要件を満たす。固定は明示代替のときのみ）
- 採用本文が画像と分離したテキストとして入り、頁 ID／読み順の対応が確認済み
- 再フロー時は文字サイズ・幅変更の確認記録がある
- 構造検証と読書環境確認が **別々に** 記録され、**検証不合格が解消**されている
- メタデータ・目次・権利／開示表示を **人が** 確認し、読み味確認の記録がある
- 本工程で触った素材の権利が `rights.md` 上クローズ（または「不使用」）している
- 成果物の `確定` と公開ステータスが混同されていない
- brief の Kindle パスと矛盾しない（明示開始時は brief へ書き戻し済み）

## やらないこと

- 未確定の本文・絵で「納品 EPUB」と宣言する（プロトタイプは目的を分けて記録）
- 「出荷可能」など共有語彙外の曖昧な完了宣言
- 再フロー必須なのに固定レイアウトで代用する
- 構造チェック合格だけで読書環境・読み味確認を省略する
- 権利・開示を成果物／付帯文に載せないまま配信する
- 特定変換ソフト名をスキル正本に固定する（案件記録には版ごと残してよい）
- 人の確認なしにメタデータ／目次を「確定」と書く
- 実ファイルなし・ブロッカー未記載のまま完了にする
